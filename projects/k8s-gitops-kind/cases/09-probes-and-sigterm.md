# readiness는 트래픽에서 빼고 liveness는 재시작하며, SIGTERM이 앱에 닿지 않으면 종료에 30초가 걸린다

> 컨테이너가 이상해지거나 멈출 때의 동작을 두 가지로 확인했다. ① **probe 실패 세 가지**(readiness 실패, liveness 실패, 프로세스 crash)가 누가 감지하고 무엇이 일어나는지 ② 같은 이미지를 exec form과 shell form으로 실행했을 때 종료 시간. 앞의 결과는 [무중단 배포](03-graceful-shutdown.md)와 [장애 시나리오 11개](04-failure-series.md)의 전제가 된다.

**조건** probe 실험: 파드 하나에만 실패를 걸고 나머지 파드는 건드리지 않음, 부하는 `/info`를 0.2초 간격으로 · readiness 5초 × 3회, liveness 10초 × 3회, startup 2초 × 15회 · 종료 실험: 같은 이미지를 로컬 컨테이너와 Kubernetes 파드로 · 공통 [환경](../README.md#환경)

## 실험 1. probe 실패 세 가지

| | readiness 실패 | liveness 실패 | crash 1회 |
|---|---|---|---|
| 감지 | probe 연속 3회 실패 | probe 연속 3회 실패 | 프로세스 종료를 바로 감지(probe 아님) |
| 첫 실패 → 조치 | 10초 뒤 `0/1`, endpoints 제외 | 20초 뒤 재시작 | 즉시 |
| 파드·컨테이너 | 그대로(`RESTARTS` 변화 없음) | 같은 파드, 새 컨테이너(0 → 1) | 같은 파드, 새 컨테이너(1 → 2) |
| endpoints에서 빠진 시간 | 49초 | 16초. **첫 실패 뒤 29초 동안은 남아 있었다**(재시작 전 20초 + 재시작 중 9초) | 13초 |
| 복구 | 복구 호출 직후 1초 안에 | 재시작으로 저절로 | 재시작으로 저절로 |

부하 2,674건이 **전부 `200`**이었고 가장 느린 응답은 0.011초였다. 파드 4개가 받아 주었기 때문이다.

## 실험 2. SIGTERM은 앱까지 가는가

| | exec form (`CMD ["uvicorn", ...]`) | shell form (`sh -c "uvicorn ..."`) 로컬 컨테이너 | shell form 파드 |
|---|---|---|---|
| PID 1 | uvicorn | `/bin/sh` | `/bin/sh` |
| 종료까지 | **0.95초**, 종료 코드 0 | **9.64초**, 종료 코드 137(SIGKILL) | **30.5초** |

## 내가 내린 판단

- **readiness는 제외만 하고 liveness와 crash는 재시작한다.** readiness가 실패해도 컨테이너는 죽지 않고 트래픽만 끊긴다. liveness는 연속 실패를 기다려야 해서(주기 10초 × 3회이므로 첫 실패부터 세 번째 실패까지 20초) 재시작되기 전 20초 동안은 이상한 파드가 endpoints에 남아 있다. 재시작이 끝나 새 컨테이너가 뜰 때까지 9초가 더 걸려, 실제로 남아 있던 시간은 29초였다. 감지 시간이 주기와 실패 횟수로 정해진다는 점을 알고 값을 정해야 한다.
- **liveness 재시작은 파드는 그대로 두고 컨테이너만 바꾼다.** 같은 파드 이름과 IP로 `RESTARTS`만 오른다. 롤아웃이나 노드 장애로 파드가 새로 만들어지는 것과 구분해서 읽는다.
- **SIGTERM은 PID 1에만 간다.** `sh -c`로 감싸면 sh가 PID 1이 되어 신호를 자식(uvicorn)에게 넘기지 않고, 앱은 종료 신호를 모른 채 환경의 제한 시간(로컬 10초, 파드 30초)을 끝까지 채운 뒤 SIGKILL로 끝난다. 파드 종료에 30초가 걸린 것은 앱이 신호를 못 받아 제한 시간을 다 쓴 결과다. 롤링 업데이트나 노드 drain처럼 파드를 내리는 작업은 모두 그만큼 늦게 끝난다.

**한계** liveness 재시작 중 파드가 endpoints에 남아 있던 9초 동안 요청이 실패하지 않은 이유(다른 파드 선택인지 인그레스 재시도인지)는 확인하지 않았다. 파드의 종료 코드는 확인하지 못했고 137은 로컬 컨테이너에서만 확인했다.
